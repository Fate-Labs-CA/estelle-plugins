# v0.0.9

## Explicit setup after native installation

The installed runtime now ships `setup <host>` with a nonmutating preview and an explicit `--apply`
mode. Follow the [migration guide](../migration/from-cli.md#deterministic-setup) using the actual installed
package directory. The shipped install/update prompts and skill instruct the installer agent to invoke this command once
after native installation. This is a step in the explicitly requested installer-agent workflow; a raw
native plugin-add command and SessionStart do not run it automatically.

Automated legacy cleanup currently supports **Codex on POSIX only**. It requires the canonical
`ESTELLE_API_KEY` inherited by the setup process, validates the installed package and canonical MCP
descriptor, and performs one bounded authenticated MCP `initialize` check. It removes only recognized
legacy Estelle user hook commands and the exact matching separate lowercase MCP registration. Foreign
hooks and unfamiliar registrations remain. Complete bounded reads, stale-plan checks and exclusive
setup locking prevent uncertain input from being treated as a complete plan.

A missing environment key, including an OAuth-only installation, remains `pending_auth` with no native
or configuration changes. Setup does not read credential files or export a native OAuth login.
Claude Code, Kimi, Grok and Cursor automated cleanup remain `pending_unsupported_host`; Codex Windows
apply remains `pending_unsupported_platform`. These pending states are explicit, not a completed repair.

## Limits and verification

Setup does not grant hook trust, change global permissions, remove project hooks or old plugin
registrations, repair an active 0.0.7/0.0.8 cache command, or reload a running host. Use the host's normal
approval and reload flow. Configuration must stay exclusively controlled during setup; native MCP
removal and file replacement cannot atomically fence an uncooperative editor. An ambiguous removal or
commit stops as `unknown` or `partial` without retry or an authentication-bearing backup.

Report package installation, authenticated MCP initialization and observed hook execution separately.
Initialization does not prove tool access, hook execution, capture upload or complete history. No paid
model, cloud launch or native customer installation is part of the fixture checks.

Local controls exercise the shared runtime and generated packages. The existing three-OS Node 22
workflow runs package tests and generated-file checks; these are not five-host native installation
certification. Automatic repair after raw native plugin-add remains an integration gap. This release
wires the deterministic command into the documented installer-agent workflow, with no per-session or
per-tool migration.
