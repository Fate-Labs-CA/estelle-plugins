# v0.0.8

## Observed pull request targets

Codex 0.166 completion records can now contribute a separate pull request target candidate when a
completed `gh pr create` command has exit code zero and its bounded output is exactly a canonical
GitHub PR URL for the resolved repository. Original completion records and replay IDs remain intact;
command output is not stored as part of the candidate. Unsupported commands, compound shell input,
foreign targets and oversized output do not establish a link.

With the corresponding hosted-service support, Estelle verifies the target through the caller's
current connected repository before adding a linked observation. This is evidence of a verified
target reported by the client, not proof that the session created the PR. Diff, Prism, Tour and
Commits continue to use their existing target readers and permissions. This release does not add
passive ownership tracking for arbitrary workspace edits or commits.

Verification uncertainty is recorded as quiet partial local status, including during replay and
deferred drains. Direct uploads retain existing ACK-based cursor advancement; acknowledged spool batches are removed
without association retry. At most one fresh candidate is
verified per ingestion request. Additional candidates remain explicitly partial. Already-consumed
transcripts are not backfilled.

## Named Codex hook status

Codex command hooks now carry the supported `statusMessage` field with an `Estelle: <event>` label.
Commands, event selection, timeouts and credential-pattern protection are unchanged. A label identifies
the hook; it does not certify that capture, source review or tests passed. Other hosts retain their
existing manifest fields.

## Update and limits

Update through the matching [host guide](../install/) and use its supported reload or a fresh session
with normal hook approval. Installing an update does not replace an active session's loaded hooks.
No manual editing of unrelated hooks or global permissions is required by this release.

Shared-runtime and adapter tests cover all five generated packages. They do not certify every native
host on every operating system. Grok and Cursor capture-format limits remain in
[Host support](../SUPPORT.md). No paid Tour generation is part of the captured-target fixture checks.
