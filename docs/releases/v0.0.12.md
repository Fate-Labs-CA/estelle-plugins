# v0.0.12

## Claude Code signs in with OAuth

The Claude Code package's MCP entry is now only the server URL. To sign in, install the package, restart
Claude Code, run `/mcp`, choose **Estelle** and use your browser. MCP needs no key.

Before this release the entry pinned `Authorization: Bearer ${ESTELLE_API_KEY}`. With the variable unset, the
header went out literally, the server rejected it, and a rejected static header has no OAuth fallback.
With no key, `claude mcp list` now says `Needs authentication` instead of `Failed to connect`.

## `setup claude` replaces an old install

`setup claude` changes nothing and reports one of two paths: `fresh` means nothing to migrate, and `migrate`
lists what it found. Installing Estelle on Claude Code does not need `--apply`. Run `setup claude --apply`
only to replace an old install.

Apply refuses until `estelle@estelle-plugins` is installed. It removes exact legacy `estelle hook` commands
from user settings, runs `claude plugin uninstall estelle@fatelabs --keep-data --scope user`, and reads the
plugin list back. Sessions, saved memory and unrelated settings stay.

## Smaller changes

- `doctor` sends the key to the server. A revoked key used to pass because it was present; a 401 now
  reports `key_check: rejected` and exits 1.
- Setup warns when `ESTELLE_API_KEY` is exported more than once, with a count and file names only.
- The Cursor, Kimi and Grok prompts drop a setup step that could only report `pending_unsupported_host`.
- The skill and instructions name Twice, Silos, Security, CI, Orchestra and Atlas beside their tools, and
  point at `estelle_docs`.

## Limits

- **OAuth is only proven on Claude Code.** Codex, Kimi Code, Grok Build and Cursor keep the key flow. The
  tests behind this release stopped at `Needs authentication`; they did not complete a browser sign-in.
- **The two logins may be different accounts.** OAuth login and the hook key can resolve to different
  accounts, and nothing compares them. Setup reports `accounts_match: not_proved`. With a key from one
  account and a sign-in to another, sessions are captured to the first and read from the second.
- **Hooks still use `ESTELLE_API_KEY`.** Without it, MCP works and session capture is off.
- **Plugin PR #15 is not included.** That is the separate capture-only OAuth proposal.
- **Windows.** `setup claude --apply` and `setup codex --apply` report `pending_unsupported_platform` and
  change nothing, so an old install stays. Windows CI proves that refusal, not the migration, and the
  `claude` command itself has not been run on Windows.
- **The real `estelle@fatelabs` package was not uninstalled in testing.** A local fixture with that id stood
  in for it. Those tests also used a local copy of the marketplace, not this GitHub release.
- **Left in place.** Removing a group's last legacy command leaves `{"hooks": []}`. A hand-added `estelle` MCP
  server, the `fatelabs` marketplace entry, and project or local scope installs also stay.
- **Claude Desktop.** The guide says Desktop reads login-shell exports only when it starts. This release did
  not independently verify that.

This release does not change hook trust, native approvals or active sessions.
