# v0.0.13

## On Codex, approve the hooks once after this update

Run `/hooks` and press `t`, or choose **Trust all and continue** when Codex starts. Until you do, Codex shows
`Hook failed: plugin contents changed; hook approval required` for each hook it skips. Those hooks do not run,
so Estelle captures nothing and does not check file writes for credentials.

Codex asks again after any change to a plugin's files, on every update, and this release cannot change that.
What it changes is how loud it is. On a measured turn of five shell commands, Codex ran 25 Estelle hooks and now
runs 8, so a turn that has not been approved yet shows 8 failure lines rather than 25. Codex no longer starts a
process for each model request, and the write check only runs on tools that write files.

`doctor` and `setup codex` now report `review_required` with that same next step. They read Codex's hook list
and never approve anything.

## The write check stops refusing ordinary code

The check refused any name containing "token" that was assigned from something eight characters long. That
meant a max-tokens keyword from a lookup, a tokenizer name, and diff lines that only removed code. It now needs
evidence of a value:

- A vendor key shape or a private key with a body is refused wherever it appears.
- A secret-named variable holding a real-looking literal is refused.
- Names that describe a credential or count tokens are refused only if the literal looks randomly generated.
- References, type hints, placeholders, templates and sentences pass.
- Text being removed is no longer checked, so you can now delete a leaked key.

**Some things pass that used to be refused**, and a few of them could be real:

- A human-chosen value under a descriptor name, such as one ending in `_hint` or `_name`.
- A lowercase, letters-only bare value, which looks the same as a variable.
- A value made only of placeholder words, such as `test1234`.
- A passphrase that reads like a sentence.

It checks file-write tools only. It does not see shell redirection, writes through MCP tools, or an unlabelled
random string. Privacy redaction is unchanged and still hides more than this check refuses.

## Commands and skills

- **Codex gets the commands.** `estelle:code`, `estelle:cloud`, `estelle:monitor`, `estelle:resume`,
  `estelle:review` and `estelle:rooms` are now skills there. They were missing before: Codex skips any command
  that uses `$ARGUMENTS`.
- **The Claude Code menu is the six commands.** The 26 skills stay available to the model and leave the `/` menu.
  Nothing was deleted, but typing a skill by hand on Claude Code, such as `/estelle:bug-hunt`, now refuses. Ask
  Claude to use it instead.
- **Agents reach Estelle on a plugin install.** The four Claude Code agents listed tools under a name a plugin
  install does not use, so they ran with no Estelle tools and no error.
- Every skill has a short plain line, which Codex's picker prefers. `/estelle:cloud` says Twice rather than QA,
  and `/estelle:monitor` says what it reads.

## Limits

- **Tested.** Codex 0.166.0 and Claude Code 2.1.318 ran for real in a temp home against local stand-ins for the
  model and the Estelle API. Grok Build 1.0.41 validated and installed the package, with no model turn. Kimi Code
  and Cursor were not run: for those, the hook runner is exercised directly and the package is read.
- **Windows and Linux** were not run. The tests behind this release passed on macOS.
- **A Codex session that ends before you approve is not captured.** A session still open when you approve is
  captured from its start. Nothing goes back for the ones that ended.
- **Cursor, Grok and Kimi still list all 26 skills** with their full descriptions. Only Claude Code has a way to
  hide one from the menu and keep it for the model.
- **Silos are not on this release.** They pin v0.0.6, and their hook approval step does not accept this manifest.
