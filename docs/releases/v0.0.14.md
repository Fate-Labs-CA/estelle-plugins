# v0.0.14

## New host: DeepSeek Harness

`plugins/dsh` brings Estelle to DeepSeek Harness (`dsh`), which is a developer preview that says it will make
breaking changes. Install it with `dsh plugin --profile <name> add`; [the guide](../install/dsh.md) has the steps.
It needs Node.js 24.9 or newer and `pnpm`, both because dsh does.

You get Estelle's MCP tools, session capture and recall, the credential check on file writes, the shared skills, and
seven commands such as `/estelle-resume`.

## No harness telemetry

The package turns off four dsh rows on every route: `session-log-deepseek`, `session-telemetry-otel`,
`plugin-package-inventory-deepseek` and `desktop-product-telemetry`. Without this, dsh sends the session log, tool
results included, in the body of each request on its DeepSeek route. To check what dsh will actually mount:

```sh
dsh --profile <profile> --dump-config | node <plugin>/runtime/cli.mjs dsh-telemetry
```

It prints `DSH-TELEMETRY-OFF`, or names the row that is on and exits non-zero. On the DeepSeek route only, dsh still
sends an anonymous id and the session id as headers, and no row controls them.

## On Codex, approve the hooks again

This release changes the plugin's files, so Codex asks again: run `/hooks` and press `t`, or choose
**Trust all and continue** when Codex starts. Other hosts' behaviour does not change in this release.

## Limits

- **Tested** on `@deepseek-ai/dsh` 0.2.1-rc.5 and 0.2.2-rc.1, on macOS, in a temp project: a real tool call through dsh
  to production MCP, recall reaching the model, and the write check refusing a file. On Linux, an E2B box ran the package
  on 0.2.2-rc.1 with a real model answer, with capture turned off.
- **Capture has only reached a local recorder.** It has not been written to production, and the server needs a matching
  change to recognise this host's timelines.
- **No person has typed a slash command.** Only dsh's Web UI takes plugin commands, and it was not driven. The seven
  commands were listed by dsh's own registry, and one ran through its executor. Headless takes none, and dsh's SDK routes
  built-ins only.
- **The OTel row was read as off from the composed config.** No feedback export was triggered to confirm it.
- **Root agent only.** Subagents are not captured. A shell command is not write-checked.
- **Moving a session to Estelle Cloud from dsh has not been tested.**
- **Silos are not on this release until `PLUGIN_REF` moves** in the hosted repository, which pins its own version.
