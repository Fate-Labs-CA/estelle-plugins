# v0.0.16

## Session capture for people signed in with OAuth

If you signed in to Estelle through your host's OAuth login and have no `ESTELLE_API_KEY`, hooks used to capture nothing. This release
adds an explicit, separate sign-in for capture only:

```sh
node "<installed Estelle package>/runtime/cli.mjs" setup <claude|codex|cursor|kimi|grok> --capture-login
node "<installed Estelle package>/runtime/cli.mjs" setup <host> --capture-logout
```

It opens Estelle's consent page in your browser (PKCE, loopback callback). Approving it lets the hooks upload recorded session events,
including conversation text, tool results and captured file changes. The grant cannot call recall, checkpoints, indexing, models,
settings, billing or MCP. Capture events do not trigger PR, work or notification observers. Details: [capture-auth](../capture-auth.md).

## What is unchanged

- A canonical `ESTELLE_API_KEY` keeps working exactly as before and wins over this sign-in; the capture store is not opened.
- The write warning from 0.0.15 still fires with a capture sign-in, and still fires if the capture credential store cannot be read.
- `doctor` reports `credential: capture_scoped` for a capture sign-in and does not probe MCP.

## Limits

- Needs a real browser sign-in against the live server, which has not been run. Tests use a stand-in server.
- The matching backend must be deployed before this is announced: the capture client, `/oauth/token`, `/oauth/revoke` and capture-only
  `/session/events`.
- POSIX only. Windows reports `pending_unsupported_platform` and changes nothing.
- Logout revokes this account's fixed capture client, so another machine signed in for capture may need to sign in again.
- `/estelle handoff` still needs a key; a capture sign-in does not enable it.
